git worktree 隔离让多 agent 改同一仓库不打架

让 3 个 agent 同时改同一个仓库，十有八九会翻车——不是 A 把 B 改的文件覆盖了，就是 C 切了个分支把 A/B 的未提交改动带飞。 最"正确"的隔离方式是每个 agent 各自 git clone 一份，但大仓（比如 CPU RTL 动辄几 GB）这么搞磁盘和时间都受不了。更轻的方案是 git worktree——共享 .git，分 Working Directory，既不重复下载，又让每个 agent 拿到独立的文件空间。 本文把 worktree 原理讲清楚，列出什么场景必须用，哪些坑必踩，最后用 picorv32 真实仓库跑一遍完整流程。 背景：三个 agent 改同一仓库的典型翻车 场景：让三个 sub-agent 并行处理 RTL 仓库—— Agent A：跑 baseline 回归测试（需要 checkout main） Agent B：改 AXI arbiter，跑新测试（需要 checkout 新分支 + modify files） Agent C：bisect 一个历史 bug（需要来回 checkout 旧 commit） 三个全部指向 ~/repos/rtl，会发生： B 正在 git checkout -b fix-axi 的时刻，A 发起 git checkout main——git 会把 B 的未提交修改一并带到 main 或直接报错。 C 的 git bisect 切到 3 年前的 commit，A 的测试 runner 以为自己在 main 上，读到了古早代码开始跑，结果全 fail。 B 保存修改后 git add -A，把 A 临时生成的 log 文件也 staged 了。 根因只有一个：git 的 working directory 与 .git 是 1:1 绑定的，所有进入这个目录的进程共享同一个 HEAD、同一个 index。 ...
