> 本文以 PiCode（一款 CLI 上的 Code Agent）为例，总结了一套与 AI 助手高效协作的方法论。无论你使用哪款 Code Agent，这些技巧都同样适用。

## 什么是 Code Agent？

Code Agent 不是一个普通的聊天机器人，它能够**读取文件、执行命令、修改代码、调用 API**，并在多个步骤之间保持上下文、自主决策。你可以把它理解为一个「会写代码的助理工程师」——你给方向，它负责落地。

PiCode 的能力边界大致如下：

| 能力 | 说明 |
|------|------|
| 读写文件 | 读取、创建、修改本地任意文件 |
| 执行命令 | 运行 shell 命令、测试、构建 |
| 调用 API | GitHub、飞书、GitLab 等外部服务 |
| 记忆上下文 | 跨会话记住项目背景和你的偏好 |
| 多步规划 | 将复杂任务拆分为步骤并依次执行 |

## 沟通技巧：怎么说，AI 才能真正理解你

### 1. 说「做什么」，而不是「怎么做」

**不好的提问方式：**
> "帮我在第 42 行后面加一个 if 判断，检查 x 是否大于 0，如果是就 return"

**好的提问方式：**
> "函数 `calculate()` 在 x 为负数时会崩溃，帮我修复这个 bug"

Code Agent 有能力自己决定最合适的实现方式，你只需要描述**目标和问题**，不需要手把手指挥每一步。

---

### 2. 提供足够的上下文

AI 不会读心术。如果你的需求有背景，请一起说出来：

```
# 弱上下文（AI 可能猜错方向）
帮我优化这个函数的性能

# 强上下文（AI 能精准执行）
这个函数每秒被调用 10 万次，当前耗时 2ms，目标是降到 0.5ms 以内，
主要瓶颈可能在字符串拼接这里，帮我优化
```

上下文的关键要素：
- **约束条件**：不能修改接口、需要向后兼容、只能用标准库...
- **目标指标**：性能要求、代码风格、部署环境
- **已知信息**：你排查过什么、排除了什么原因

---

### 3. 分阶段确认，而不是一次性抛出大任务

把「搭建一个完整的博客网站」这样的任务一次性丢给 AI，它可能会做出你不期望的技术选型。更好的方式是：

```
第一步：先告诉我方案和技术选型，我确认后再动手
第二步：先搭脚手架，我预览后再加功能
第三步：逐步迭代，每步确认
```

这样你始终保持对方向的掌控，AI 负责执行细节。

---

### 4. 用「我希望」代替「你应该」

语气上的差异会影响 AI 的回答方式：

- "你应该用 Redis 缓存" → AI 可能直接执行，即使 Redis 不适合你的场景
- "我希望提升接口响应速度，你有什么建议？" → AI 会分析场景后给出最合适的方案

给 AI 空间去思考，往往比直接指令更有效。

---

### 5. 遇到结果不对时，描述「期望」而非「指责」

**不好的反馈：**
> "不对！你改错了！"

**好的反馈：**
> "这个改动导致单元测试 #42 失败了，错误是 `KeyError: 'user_id'`，期望行为是..."

AI 需要具体的信息来修正方向，越精确的反馈，修复越快。

## 实战场景举例

### 场景一：调试线上 Bug

**你：**
> 线上有个接口偶发 500 错误，日志如下 `[粘贴日志]`，帮我找出根因

**PiCode 会做的事：**
1. 分析日志，锁定出错的文件和行号
2. 读取源码，理解上下文
3. 提出 2-3 个假设，并找证据验证
4. 给出具体修复方案和测试步骤

**关键技巧**：把完整的错误日志和堆栈信息一起提供，不要只说「报错了」。

---

### 场景二：搭建新项目

**你：**
> 我要做一个个人博客，要求：免费托管、支持 Markdown、有代码高亮、国内访问速度可以接受慢一些

**PiCode 会做的事：**
1. 推荐技术方案（Hugo + GitHub Pages）
2. 安装依赖、初始化项目
3. 配置主题、功能开关
4. 部署上线，验证可访问

**关键技巧**：说清楚你的**约束**（免费、速度要求）和**必要功能**，让 AI 做技术选型，你做最终拍板。

---

### 场景三：代码审查与重构

**你：**
> 帮我审查 `auth.py` 这个文件，关注安全性问题和可读性，不要改功能

**PiCode 会做的事：**
1. 读取文件，扫描安全风险（SQL 注入、硬编码密钥等）
2. 识别可读性问题（命名、注释、复杂度）
3. 给出改进建议，可选择性应用

**关键技巧**：明确说「不要改功能」这类边界，避免 AI 越权修改。

---

### 场景四：文档与知识整理

**你：**
> 帮我把这份 PCIe 规范 PDF 的第 3 章翻译成中文，整理成 Markdown，发布到我的博客 pcie 目录下

**PiCode 会做的事：**
1. 读取 PDF 内容
2. 翻译并整理为结构化 Markdown
3. 添加 front matter（标题、标签、日期）
4. 通过 GitHub API 发布到指定目录

**关键技巧**：指定「发布到哪里」，AI 会端到端完成，不需要你手动操作。

---

### 场景五：持续维护与监控

Code Agent 真正的价值在于**持续性**。你可以把它当作一个长期协作的工程师：

- 「帮我每周检查博客的 broken links」
- 「监控 GitHub Actions 构建，失败了告诉我原因」
- 「定期更新依赖，有 breaking change 提前提醒我」

---

### 场景六：让 PiCode 扮演一个专属角色

Code Agent 可以被赋予一个**持久角色**，从而在整个项目生命周期中以固定的身份和行为模式协作。

**示例：把 PiCode 设定为博客管理员**

```
你是我博客（wm920.github.io）的管理员，你的职责是：
1. 定期检查博客内容，建议补充方向
2. 主动撰写和发布文章
3. 保持界面整洁，发现 bug 自动修复
4. 管理文章分类和标签体系

博客技术栈：Hugo + PaperMod + GitHub Pages
本地路径：~/blog
```

把这段话放在对话开头，或者保存到 `picode.md` 文件里，PiCode 在每次对话时都会以「博客管理员」的身份行事，而不是一个被动等待指令的工具。

**角色设定的关键要素：**
- **职责边界**：明确 AI 能做什么、不做什么
- **上下文注入**：告诉 AI 项目的技术栈、路径、规则
- **主动性授权**：明确说「你可以主动发现问题并修复」

## 让 PiCode 永久记住规则

这是很多人忽视的高级用法。PiCode 有一套持久化记忆机制，可以让你**一次设定，永久生效**，不需要每次对话都重新说明背景。

### 方法一：用 `#` 前缀当场记录

在 PiCode 对话中，以 `#` 开头的输入会被直接存入记忆：

```
# 我的博客路径是 ~/blog，GitHub 用户名是 wm920
# 写文章时默认用中文，代码注释也用中文
# 发布文章前先在本地 hugo --minify 验证构建通过
# 回复我时不要用表情符号
```

这些规则会持久保存，下次打开新对话时依然有效。

### 方法二：在 `picode.md` 里写项目规则

在项目根目录创建 `picode.md`，这个文件会在每次对话时自动加载：

```markdown
# 项目：个人博客

## 基本信息
- 博客地址：https://wm920.github.io
- 本地路径：~/blog
- 技术栈：Hugo + PaperMod + GitHub Pages
- GitHub：wm920/wm920.github.io

## 行为规则
- 推送前必须先执行 `hugo --minify` 验证构建
- 文章放到对应子目录（学习笔记/flexnoc、ddr、pcie、rdma、ai-tools）
- 修改文件前先 read，不要盲目写入
- 发布后等待 GitHub Actions 完成，自行验证线上可访问

## 内容规范
- 文章标题使用中文
- 必须添加 tags 和 categories
- 技术文章要有代码示例
```

有了这个文件，你不需要每次都告诉 PiCode 博客在哪里、规则是什么——它每次打开都「记得」。

### 方法三：用 `take_note` 让 AI 主动记忆

在对话中直接告诉 PiCode 要记住某件事：

```
记住：以后我提到"发布文章"，默认是发到学习笔记对应子目录下，
不是 posts/ 目录
```

PiCode 会调用 `take_note` 工具将这条规则保存到记忆库，并在未来的对话中自动应用。

## 定时任务：让 AI 自动完成周期性工作

Code Agent 不一定需要你每次手动触发。通过定时任务机制，你可以让它**按计划自动执行**。

### 使用 `/loop` 在当前会话中循环执行

PiCode 内置 `/loop` 命令，可以让一个任务按固定间隔重复：

```bash
# 每 10 分钟检查一次博客构建状态
/loop 10m 检查 GitHub Actions 最新构建是否成功，失败的话告诉我原因

# 每小时监控一次
/loop 1h 检查 wm920.github.io 是否可访问，响应时间是否正常
```

### 使用 `CronCreate` 设置持久定时任务

`CronCreate` 可以设定即使关闭对话也会按时执行的任务：

```
帮我创建一个每天早上 9 点执行的任务：
检查博客最近 7 天有没有新文章，如果没有，根据我的技术方向写一篇草稿推送到草稿分支
```

常见的定时任务场景：

| 任务 | 建议频率 |
|------|---------|
| 检查博客 broken links | 每周一次 |
| GitHub Actions 构建监控 | 每次 push 后自动触发 |
| 博客文章草稿生成 | 每周三次 |
| 依赖版本更新检查 | 每月一次 |

## 自主博客写作：让 PiCode 成为你的专栏作者

这是目前最令人兴奋的用法之一——让 AI **自主选题、写作、发布**，你只需要偶尔审阅。

### 第一步：定义写作风格和方向

在 `picode.md` 或记忆中写明：

```markdown
## 写作风格
- 技术文章：结构清晰，有代码示例，结尾有总结
- 面向读者：有一定技术背景的工程师
- 字数：1500-3000 字为宜
- 语言：中文，技术术语保留英文原文

## 内容方向
- 芯片互联协议（FlexNOC、PCIe、DDR、RDMA）
- AI 工具使用技巧
- 读书笔记（技术类和非技术类各占一半）
```

### 第二步：给 PiCode 一个自主写作的指令

```
以我的博客管理员身份，根据我的内容方向，
每周主动写 2 篇技术文章并发布到对应目录。
选题优先考虑：
1. 我最近在学的技术方向（PCIe、RDMA）
2. AI 工具的新用法
3. 能帮助其他工程师的实用技巧
写完后告诉我文章标题和发布位置，我来审阅。
```

### 第三步：建立审阅流程

让 PiCode 先发布到草稿状态（`draft: true`），你审阅后再改为正式发布：

```
以后自动写的文章都先设置 draft: true，
我看完觉得没问题了告诉你，你再改成 draft: false 正式发布
```

### 完整的自主写作流程

```
PiCode 每周执行：
  1. 查看最近发布的文章，避免重复选题
  2. 结合当前技术热点，确定本周选题
  3. 收集相关资料（读 spec、搜索最新进展）
  4. 撰写文章，添加代码示例和图表说明
  5. 本地构建验证无误
  6. 以 draft:true 发布，通知我审阅
```

## 更深层的思考：构建你的 AI Agent 生态

单独使用一个 Code Agent 只是起点。真正的效率提升来自于**把多个能力连接起来**，形成一个为你持续工作的系统。

### 思路一：AI 驱动的个人知识库

```
PiCode 的工作流：
读 spec/论文 → 提取关键信息 → 整理为 Markdown → 发布到博客
```

当你遇到一份 PCIe spec，不再需要自己从头阅读——让 PiCode 先过一遍，提取要点，写成你能快速消化的笔记。

### 思路二：对话即操作（Conversational Operations）

把繁琐的操作隐藏在自然语言后面：

```
"把上周的日记整理一下，提取出待办事项，
 发到飞书的待办清单里"

"检查一下最近 commit，看有没有引入新的 TODO，
 如果有，帮我在 GitHub 创建对应的 issue"
```

### 思路三：渐进式自动化

不要试图一次把所有东西自动化。正确的节奏是：

1. **手动做一次**：和 PiCode 一起完成，它观察你的偏好
2. **半自动化**：PiCode 做大部分工作，你审核关键节点  
3. **全自动化**：你只看结果，有问题才介入

从搭博客、到定期维护、到自主写作，本质上就是这三个阶段的演进。

## 容易踩的坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 任务太大太模糊 | AI 会做出大量假设，结果偏离预期 | 拆小任务，分步确认 |
| 不给反馈直接重试 | AI 不知道哪里错了，会重复同样的错误 | 告诉 AI 具体哪里不对 |
| 把 AI 当搜索引擎 | 只问「XX 怎么做」而不让它直接动手 | 让 AI 直接执行，而不是给你答案 |
| 不设边界 | AI 可能「顺手」修改了你不想改的地方 | 明确说「只改 X，不动 Y」 |
| 忽略 AI 的主动提醒 | AI 发现了相邻 bug 但你没注意到 | 留意 AI 在完成任务时给出的额外观察 |

---

## 最后：把 AI 当协作者，而不是工具

最高效的使用方式，是把 Code Agent 当作一个**有能力、需要方向感**的团队成员：

- 你负责：目标、优先级、最终决策
- AI 负责：信息收集、方案设计、代码实现、验证确认

当你开始把「我要让 AI 帮我」变成「我和 AI 一起做」，你会发现工作效率的提升远超预期。
