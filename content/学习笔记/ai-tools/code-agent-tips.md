> 本文以 PiCode（一款 CLI 上的 Code Agent）为例，总结了一套与 AI 助手高效协作的方法论。无论你使用哪款 Code Agent，这些技巧都同样适用。

## 什么是 Code Agent？

Code Agent 不是一个普通的聊天机器人，它能够**读取文件、执行命令、修改代码、调用 API**，并在多个步骤之间保持上下文、自主决策。你可以把它理解为一个「会写代码的助理工程师」——你给方向，它负责落地。

PiCode 的能力边界大致如下：

| 能力 | 说明 |
|------|------|
| 读写文件 | 读取、创建、修改本地任意文件 |
| 执行命令 | 运行 shell 命令、测试、构建 |
| 调用 API | GitHub、飞书、GitLab 等外部服务 |
| 记忆上下文 | 跨会话记住项目背景和你的偏好 |
| 多步规划 | 将复杂任务拆分为步骤并依次执行 |

## 沟通技巧：怎么说，AI 才能真正理解你

### 1. 说「做什么」，而不是「怎么做」

**不好的提问方式：**
> "帮我在第 42 行后面加一个 if 判断，检查 x 是否大于 0，如果是就 return"

**好的提问方式：**
> "函数 `calculate()` 在 x 为负数时会崩溃，帮我修复这个 bug"

Code Agent 有能力自己决定最合适的实现方式，你只需要描述**目标和问题**，不需要手把手指挥每一步。

---

### 2. 提供足够的上下文

AI 不会读心术。如果你的需求有背景，请一起说出来：

```
# 弱上下文（AI 可能猜错方向）
帮我优化这个函数的性能

# 强上下文（AI 能精准执行）
这个函数每秒被调用 10 万次，当前耗时 2ms，目标是降到 0.5ms 以内，
主要瓶颈可能在字符串拼接这里，帮我优化
```

上下文的关键要素：
- **约束条件**：不能修改接口、需要向后兼容、只能用标准库...
- **目标指标**：性能要求、代码风格、部署环境
- **已知信息**：你排查过什么、排除了什么原因

---

### 3. 分阶段确认，而不是一次性抛出大任务

把「搭建一个完整的博客网站」这样的任务一次性丢给 AI，它可能会做出你不期望的技术选型。更好的方式是：

```
第一步：先告诉我方案和技术选型，我确认后再动手
第二步：先搭脚手架，我预览后再加功能
第三步：逐步迭代，每步确认
```

这样你始终保持对方向的掌控，AI 负责执行细节。

---

### 4. 用「我希望」代替「你应该」

语气上的差异会影响 AI 的回答方式：

- "你应该用 Redis 缓存" → AI 可能直接执行，即使 Redis 不适合你的场景
- "我希望提升接口响应速度，你有什么建议？" → AI 会分析场景后给出最合适的方案

给 AI 空间去思考，往往比直接指令更有效。

---

### 5. 遇到结果不对时，描述「期望」而非「指责」

**不好的反馈：**
> "不对！你改错了！"

**好的反馈：**
> "这个改动导致单元测试 #42 失败了，错误是 `KeyError: 'user_id'`，期望行为是..."

AI 需要具体的信息来修正方向，越精确的反馈，修复越快。

## 实战场景举例

### 场景一：调试线上 Bug

**你：**
> 线上有个接口偶发 500 错误，日志如下 `[粘贴日志]`，帮我找出根因

**PiCode 会做的事：**
1. 分析日志，锁定出错的文件和行号
2. 读取源码，理解上下文
3. 提出 2-3 个假设，并找证据验证
4. 给出具体修复方案和测试步骤

**关键技巧**：把完整的错误日志和堆栈信息一起提供，不要只说「报错了」。

---

### 场景二：搭建新项目

**你：**
> 我要做一个个人博客，要求：免费托管、支持 Markdown、有代码高亮、国内访问速度可以接受慢一些

**PiCode 会做的事：**
1. 推荐技术方案（Hugo + GitHub Pages）
2. 安装依赖、初始化项目
3. 配置主题、功能开关
4. 部署上线，验证可访问

**关键技巧**：说清楚你的**约束**（免费、速度要求）和**必要功能**，让 AI 做技术选型，你做最终拍板。

---

### 场景三：代码审查与重构

**你：**
> 帮我审查 `auth.py` 这个文件，关注安全性问题和可读性，不要改功能

**PiCode 会做的事：**
1. 读取文件，扫描安全风险（SQL 注入、硬编码密钥等）
2. 识别可读性问题（命名、注释、复杂度）
3. 给出改进建议，可选择性应用

**关键技巧**：明确说「不要改功能」这类边界，避免 AI 越权修改。

---

### 场景四：文档与知识整理

**你：**
> 帮我把这份 PCIe 规范 PDF 的第 3 章翻译成中文，整理成 Markdown，发布到我的博客 pcie 目录下

**PiCode 会做的事：**
1. 读取 PDF 内容
2. 翻译并整理为结构化 Markdown
3. 添加 front matter（标题、标签、日期）
4. 通过 GitHub API 发布到指定目录

**关键技巧**：指定「发布到哪里」，AI 会端到端完成，不需要你手动操作。

---

### 场景五：持续维护与监控

Code Agent 真正的价值在于**持续性**。你可以把它当作一个长期协作的工程师：

- 「帮我每周检查博客的 broken links」
- 「监控 GitHub Actions 构建，失败了告诉我原因」
- 「定期更新依赖，有 breaking change 提前提醒我」

## 容易踩的坑

| 坑 | 说明 | 对策 |
|----|------|------|
| 任务太大太模糊 | AI 会做出大量假设，结果偏离预期 | 拆小任务，分步确认 |
| 不给反馈直接重试 | AI 不知道哪里错了，会重复同样的错误 | 告诉 AI 具体哪里不对 |
| 把 AI 当搜索引擎 | 只问「XX 怎么做」而不让它直接动手 | 让 AI 直接执行，而不是给你答案 |
| 不设边界 | AI 可能「顺手」修改了你不想改的地方 | 明确说「只改 X，不动 Y」 |
| 忽略 AI 的主动提醒 | AI 发现了相邻 bug 但你没注意到 | 留意 AI 在完成任务时给出的额外观察 |

---

## 最后：把 AI 当协作者，而不是工具

最高效的使用方式，是把 Code Agent 当作一个**有能力、需要方向感**的团队成员：

- 你负责：目标、优先级、最终决策
- AI 负责：信息收集、方案设计、代码实现、验证确认

当你开始把「我要让 AI 帮我」变成「我和 AI 一起做」，你会发现工作效率的提升远超预期。
