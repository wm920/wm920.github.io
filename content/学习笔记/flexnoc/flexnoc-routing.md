> 路由算法决定数据包在 NOC 中从源到目的地的路径选择策略，直接影响系统的延迟、带宽利用率和死锁风险。本文深入解析 FlexNOC 支持的主要路由算法，并给出工程实践中的选型建议。

## 路由算法的核心问题

在片上网络中，路由算法需要解决三个核心问题：

1. **路径选择**：从 A 到 B 有多条路径，选哪条？
2. **死锁避免**：循环依赖会导致永久阻塞，如何避免？
3. **负载均衡**：如何防止部分链路过载而其他空闲？

不同算法在这三个维度上的权衡决定了它们的适用场景。

## 一、确定性路由：XY 路由算法

XY 路由是 Mesh 拓扑中最广泛使用的确定性路由算法，也是 FlexNOC Mesh 配置的默认选项。

### 工作原理

数据包的路径分两个阶段确定：
1. **X 阶段**：沿 X 轴（水平方向）路由，直到到达目标列
2. **Y 阶段**：沿 Y 轴（垂直方向）路由，直到到达目标行

```
4×4 Mesh 中从 R(0,3) 到 R(3,1) 的 XY 路由路径：

R(0,3) → R(1,3) → R(2,3) → R(3,3)    ← X 阶段（列 0→3）
                                  ↓
                            R(3,2) → R(3,1)    ← Y 阶段（行 3→1）
```

### 路由函数

对于源节点 $(x_s, y_s)$ 到目标节点 $(x_d, y_d)$：

```
if x_current ≠ x_dest:
    next_hop = (x_current + sign(x_dest - x_current), y_current)
else:
    next_hop = (x_current, y_current + sign(y_dest - y_current))
```

### 死锁证明

XY 路由天然无死锁，原因在于它将二维通道分成了有序的两类：
- **X 通道**：始终单向（向右或向左）
- **Y 通道**：X 阶段结束后才使用

这种严格的通道顺序使得依赖环不可能形成。

```
死锁需要的循环依赖在 XY 路由中不存在：
✗ 不可能：X通道 → Y通道 → X通道（XY路由一旦转入Y通道就不会再用X通道）
```

### 局限性

| 问题 | 说明 |
|------|------|
| 路径唯一 | 同一 (src, dst) 对只有一条路径，无法绕过拥塞点 |
| 热点效应 | 流量集中在特定链路，边界节点更明显 |
| 不均衡 | 角落节点到中心节点路径长，延迟差异大 |

## 二、源路由（Source Routing）

源路由将完整路径编码在数据包头部，每个路由器只需按头部指示转发，无需本地路由计算。

### 数据包头部结构

```
┌─────────────────────────────────────────────┐
│  Dir[0] │ Dir[1] │ Dir[2] │ ... │ Payload   │
│  (2bit) │ (2bit) │ (2bit) │     │           │
└─────────────────────────────────────────────┘
Dir 编码：00=本地交付  01=向东  10=向西  11=向南  ...
```

每经过一个路由器，消耗头部最前面的方向字段，剩余字段继续携带。

### 优势

- **路由器极简**：无需存储路由表，逻辑面积小
- **灵活路径**：源端可以指定任意合法路径，便于流量工程
- **适合 Ring 拓扑**：Ring 的环形路径天然适合用源路由编码

### FlexNOC 中的应用

FlexNOC 在 Ring 拓扑中默认使用源路由。系统初始化时，软件或硬件仲裁逻辑预计算每对 (master, slave) 的最优路径并写入配置寄存器，运行时无需动态计算。

```
配置流程：
1. FlexNOC 配置工具根据拓扑自动计算所有源路由表
2. 在系统上电时通过 APB/AHB 接口写入各 master 的路由配置寄存器
3. 运行时 master 直接使用预配置的路径，零额外延迟
```

## 三、自适应路由（Adaptive Routing）

自适应路由允许数据包根据网络实时状态（拥塞程度、队列深度）动态选择路径，是提升网络吞吐量的关键技术。

### 工作原理

```
数据包到达路由器时：

┌─────────────────────────────────────┐
│  计算所有合法下一跳（满足无死锁条件）  │
│              ↓                       │
│  读取每个候选出口的队列深度           │
│              ↓                       │
│  选择队列最短（或负载最轻）的出口      │
└─────────────────────────────────────┘
```

### 死锁避免：转向模型

自适应路由最大的挑战是死锁。FlexNOC 采用**转向限制模型（Turn Model）**保证无死锁：

```
West-First 路由（限制向西的转向）：
✓ 允许的转向：N→E, S→E, E→N, E→S, W→N, W→S
✗ 禁止的转向：N→W, S→W, E→W（即不允许转向西方）

效果：打破了循环依赖，同时保留了大量路径选择自由度
```

常见的转向限制策略：

| 策略 | 禁止转向 | 路径自由度 |
|------|---------|-----------|
| West-First | 任何转向西方的转 | 高 |
| North-Last | 任何离开北方的转 | 高 |
| Negative-First | 负方向的转 | 中 |
| Odd-Even | 基于列号奇偶限制 | 中高 |

### 性能对比：XY vs 自适应

```
均匀随机流量下的吞吐量对比（4×4 Mesh 仿真结果示意）：

注入率  XY路由吞吐  自适应路由吞吐
 0.1      0.10        0.10
 0.3      0.30        0.30
 0.5      0.48        0.50
 0.7      0.52        0.67    ← 自适应路由优势开始显现
 0.9      0.53        0.72
```

自适应路由在高负载时优势显著，但代价是路由器逻辑更复杂（需要实时感知邻居队列状态）。

## 四、虚通道（Virtual Channel）机制

虚通道不是独立的路由算法，而是配合路由算法使用的关键机制，在 FlexNOC 中广泛应用。

### 基本概念

物理链路上分时复用多条逻辑通道（Virtual Channel），每条 VC 有独立的缓冲队列：

```
物理链路
    ↓
┌──────────────────────┐
│  VC0: [pkt] [pkt]    │  ← 高优先级流量
│  VC1: [pkt] [  ]     │  ← 普通流量
│  VC2: [   ] [   ]    │  ← 低优先级流量
└──────────────────────┘
```

### 在 FlexNOC 中的作用

1. **死锁避免**：不同 VC 之间无依赖，可用于隔离可能死锁的流量类别
2. **QoS 支持**：高优先级流量分配到专用 VC，低延迟保证
3. **吞吐量提升**：一条 VC 因 HoL（Head-of-Line）阻塞时，其他 VC 可继续传输

## 路由算法选型指南

```
拓扑是 Ring？
  ├─ YES → 源路由（FlexNOC 默认）
  └─ NO（Mesh/Tree）→ 性能要求是否极高？
      ├─ NO，面积/功耗敏感 → XY 路由（简单可靠）
      └─ YES，需要高吞吐 → 自适应路由 + 虚通道
          └─ 需要 QoS 隔离？
              ├─ YES → 多 VC + West-First 自适应
              └─ NO  → 单 VC 自适应路由即可
```

## 工程实践要点

1. **优先使用 XY 路由**：除非流量分析明确显示热点问题，XY 路由的简单性和可预测性是首选
2. **虚通道数量**：FlexNOC 通常配置 2-4 个 VC 已足够，过多 VC 会增加缓冲面积
3. **源路由预计算**：Ring 拓扑的源路由表由 FlexNOC 配置工具自动生成，无需手动计算
4. **自适应路由调试**：自适应路由的不确定性使得仿真波形分析更复杂，需要专门的 NOC 监控工具（如 AXI Monitor）辅助定位问题
